### 2.3 ac_runtime 배치 API 재작성

대상 파일: `src/backend/vulkan/ac_vk_dispatch.cpp`, `ac_vk_event.cpp`, `src/runtime/ac_runtime.cpp`, `include/ac_runtime.h`

**기존 결함:**
- 완료 이벤트를 파괴하면 배치의 VkFence가 파괴되고, 이어서 배치를 파괴할 때 같은 펜스를 대기·파괴했습니다(이중 파괴).
- 배치당 디스패치가 8회로 제한되었습니다.
- 배치 끝에 SHADER_WRITE→HOST_READ 배리어가 없었습니다.
- WAR 위험을 추적하지 않았습니다.
- 디스패치마다 디스크립터 풀을 생성했습니다.
- 제출에 실패하면 Vulkan 객체가 누수되었습니다.

**변경 내용:**
- 제출 객체를 배치와 이벤트가 참조 카운트로 공유합니다.
- 새 API를 추가했습니다(기존 구조체 레이아웃은 그대로):
  - `ac_runtime_batch_begin_ex`
  - `ac_runtime_batch_dispatch_bindings` (버퍼 범위 바인딩)
  - `ac_runtime_batch_barrier`
  - `ac_runtime_batch_get_stats`
  - `ac_runtime_context_get_limits`
- 디스크립터 세트 캐시를 컨텍스트 단위로 두고, 버퍼·커널 파괴 시 해당 세트를 정리합니다.

**검증:** `tests/test_batch_api_kat.cpp`(실측 게이트로 수정)와 `tests/test_batch_graph_kat.cpp`(신규)가 S25·A35 모두 PASS입니다.
- 1,000회 의존 디스패치 연쇄 결과:

| 기기 | wall | GPU |
|---|---|---|
| S25 | 24.5 ms | 7.2 ms |
| A35 | 21.2 ms | 19.4 ms |

- 디스크립터 캐시 적중은 2회차에 1000/1000입니다.

### 2.4 그래프 엔진

대상: `adapters/llama/ggml-ameva/ggml-ameva.cpp` 전면 재작성, 커널 `shaders/ameva_*.comp`

**동작 방식:**
- `graph_compute` 한 번이 배치 하나, 제출 하나입니다.
- 텐서 바이트 범위로 RAW/WAR/WAW를 추적하고, 필요한 곳에만 배리어를 넣습니다.
- 모든 텐서는 정렬된 범위로 바인딩합니다. 가중치가 바인딩 한계를 넘으면 행 단위로 나눠 실행합니다.
- SET_ROWS/GET_ROWS의 인덱스가 범위를 벗어나면 GPU 상태 버퍼에 기록되고, 호스트가 FAIL-FAST합니다.
- `supports_buft`는 AMEVA 버퍼만 허용합니다. 백엔드가 몰래 스테이징하던 경로는 제거했고, 입력 복사는 스케줄러가 합니다.
- `supports_op`는 NONE/VIEW/RESHAPE/PERMUTE/TRANSPOSE를 허용합니다. 이전에는 거부해서 split이 늘었고, `test-backend-ops`가 모든 케이스를 건너뛰었습니다.

**정밀도:**
- f16 변환은 소프트웨어 RNE·서브노멀까지 정확하게 처리합니다.
- ROPE의 sin/cos는 Cody-Waite 축약과 다항식으로 직접 구현했고, 각도 계산은 CPU와 같은 반복 곱셈을 씁니다.

**검증:** S25 `~/abi-lab/tbo/tbo_all_g2.log`에서 1692/1692 통과, 실패 0건입니다.
- 연산별 통과 수:
  - FLASH_ATTN_EXT 824, MUL_MAT 187, ROPE 132
  - RMS_NORM_MUL_ROPE 72, SET_ROWS 42, ADD 42, CPY 40, SUB/MUL/DIV 각 34
  - RMS_NORM_MUL_ADD 30, MUL_MAT_VEC_FUSION 30, ADD_RMS_NORM 25, ROPE_SET_ROWS 24
  - RMS_NORM 21, CONT 18, GET_ROWS 10, GLU 계열 34
  - UNARY 계열, SCALE, SOFTCAP 등

### 4.1 새 엔진 실모델 패리티 (S25)

1. 소스를 동기화하고 도구를 재빌드합니다.

   ```

   ssh s25 'bash ~/abi-lab/llm_parity_setup.sh'
   ```

## 6. 알려진 문제와 주의사항

- `$PREFIX/include/llama.h`는 설치된 libllama(b8471)보다 새 버전의 헤더라 구조체 레이아웃이 다릅니다. 반드시 `~/abi-lab/llama-b8471/include`를 쓰십시오.

**작업 환경 함정**
- Termux에서는 `/tmp`에 쓸 수 없습니다. `~/abi-lab/tmp`나 `$TMPDIR`을 쓰십시오.
- 로컬 ssh가 오래 걸리면 도구 시간 제한으로 끊깁니다. 원격 장시간 작업은 `(nohup ... &)` 형태로 띄우고 결과 파일을 확인하십시오.
- 셸 heredoc에서 백슬래시가 변형됩니다. 이스케이프가 들어간 편집은 편집기 도구로 하십시오.

**KLD 해석**
- KLD 비교에는 CPU 자체의 근사가 섞입니다.
  - CPU FA: V를 f16으로 누적하고 Q를 f16으로 변환
  - CPU GELU: f16 테이블 사용
  - CPU 양자화 연산: 활성값 Q8 양자화
- 정확도 판정에는 `--ref-model`(F32 역양자화)과 `--kv f32`를 쓰십시오.

**성능**
- A35 Mali에서 QMM 커널 효율이 낮습니다(Q2_K 4B 기준 메모리 대역폭의 약 6%).

**미확인 동작**
- `unpackHalf2x16`의 f16 서브노멀 처리(FTZ 여부)를 Adreno/Mali에서 확인하지 않았습니다.
  - QMM 커널은 아직 이 내장 함수를 씁니다.
  - 새 연산 커널은 소프트웨어 변환을 씁니다.

## 7. 사용자 협의가 필요한 결정

- `third_party/whisper.cpp`: `.gitmodules`는 서브모듈로 선언되어 있으나, 브랜치는 파일 3개를 직접 추적하고 있습니다. 서브모듈로 갈지 직접 포함(vendor)으로 갈지 정해야 합니다. STT 배포 단계 전에 결정이 필요합니다.
- ameva-runtime 배포기(별도 저장소): 번들을 `$PREFIX/lib`에 복사하고 RUNPATH를 `$PREFIX/lib`로 두는 것이 라이브러리 혼재의 근원입니다. `$ORIGIN/../lib`로 바꾸는 수정이 필요합니다.
- 새 엔진을 `$PREFIX/lib`에 설치하는 시점(§4.5 검증 후)
- A53은 보류 중입니다.
